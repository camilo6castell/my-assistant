## 📡 Overview

MyAssistant is a **fully local, privacy-first Retrieval-Augmented Generation (RAG) system** designed as a personal semantic memory infrastructure. It allows querying multiple independent knowledge domains — psychoanalysis, philosophy, technical documentation, sociology, etc. — through an adaptive LangGraph pipeline that retrieves, evaluates, reformulates, generates, and reviews answers before returning them to the user.

**Core design principles:**

**Isolation** — each knowledge domain lives in its own FAISS index. Contexts never bleed into each other.

**Control** — every component of the pipeline (chunking, embedding, retrieval, routing, generation, review) is explicit and tunable. No black-box abstractions.

**Privacy by design** — the answer to every query is always generated by the local model. External providers (Gemini) only see short, context-free inputs for internal operations (query reformulation, answer review). Your indexed documents never leave the machine.

**Honesty** — the LLM is hard-constrained by the prompt to answer only from retrieved context. When the answer is not in the documents, it says so.

## 🔄 RAG Graph

The retrieval pipeline is implemented as a **LangGraph stateful graph** (`RAGState`). Each node receives the full state and returns only the fields it modifies — LangGraph merges them. Nodes have no knowledge of routing: that logic lives exclusively in the conditional edges.

### Nodes

| Node               | Provider      | Responsibility                                     |
| ------------------ | ------------- | -------------------------------------------------- |
| `retrieve_node`    | local (FAISS) | Cosine search + re-ranking over active collections |
| `evaluate_node`    | —             | Logs routing decision (no state mutation)          |
| `reformulate_node` | Gemini        | Rewrites query to improve semantic recall          |
| `generate_node`    | local LLM     | Builds prompt from chunks + calls local model      |
| `review_node`      | Gemini        | Evaluates anchoring and source citation via JSON   |
| `correct_node`     | local LLM     | Regenerates answer incorporating reviewer feedback |

### Routing

```
evaluate_node  → reformulate  if confidence < CONFIDENCE_LIMIT and not yet reformulated
evaluate_node  → generate     otherwise
review_node    → END          if review passed (or MAX_REVIEW_ATTEMPTS reached)
review_node    → correct      if review failed
correct_node   → review       (loop, capped)
```

### State fields

```python
class RAGState(TypedDict):
    question: str  # current question (may be reformulated)
    mode: str  # ChatMode.SOFT | ChatMode.HARD
    collections: list[LoadedCollection]
    chat_memory: list[TurnMemory]  # sliding window of N turns
    results: list[SearchResult]  # retrieved chunks
    confidence: float  # avg cosine score of top-K results
    reformulated: bool  # True after one reformulation (prevents loops)
    answer: str  # current generated answer
    review_passed: bool  # True if reviewer approved
    review_feedback: str  # rejection reason for correct_node
    review_attempts: int  # increments per review cycle
```

## 🔀 Multi-Provider LLM

The system uses a **provider-per-role** architecture (`src/nlp/llm/providers.py`). Each role in the pipeline (`LLMRole` in `src/nlp/llm/roles.py`) can use a different backend + model without any change to `graph.py` or `nodes.py`. Backends and per-role model choices are configured in `.env.providers` and resolved at runtime from a cached factory.

### Two independent axes

- **Backend** — a concrete runtime: `flm` (FastFlowLM) | `ollama` | `gemini`. Configured once with its URL (and credential, for Gemini):

  ```bash
  LLM_FLM_URL=http://127.0.0.1:52625/v1
  LLM_OLLAMA_URL=http://127.0.0.1:11434
  LLM_GEMINI_URL=https://generativelanguage.googleapis.com/v1beta/openai/
  GEMINI_API_KEY=...
  ```

- **Role** — picks a `backend,model` pair directly:

  ```bash
  LLM_ROL_GENERATE=flm,qwen3.5:9b
  LLM_ROL_REFORMULATE=ollama,qwen3.5:2b
  LLM_ROL_REVIEW=gemini,gemini-2.5-flash-lite
  LLM_ROL_SUPPLEMENT=flm,qwen3.5:9b
  ```

Roles sharing the same `backend,model` (above, generation and web-supplement both use `flm,qwen3.5:9b`) share a single cached client instead of opening a duplicate connection.

### Default routing (example above)

| Role                | Backend | Rationale                                             |
| ------------------- | ------- | ------------------------------------------------------ |
| Query reformulation | ollama  | Short, context-free input — a small model is enough    |
| Answer generation   | flm     | Full context (chunks) never leaves the machine         |
| Answer review       | gemini  | Evaluates the answer text, not the documents            |
| Web supplement      | flm     | Same as generation — stays local                        |

### Privacy guarantee

Gemini (or any external backend assigned to a role) only ever receives what that role's prompt sends it — for `review`, the generated answer text, not the retrieved chunks. Assign an external backend to `generate`/`supplement` only if you're fine with the retrieved chunks leaving the machine.

### Adding a model to an existing backend

One entry in `src/config/models/<backend>.py` (`flm.py` | `ollama.py` | `gemini.py`) with its capabilities (`max_tokens`, `think_mode`, context window). No new environment variable needed.

### Adding a new backend

One entry in the registries at the top of `src/nlp/llm/providers.py` (`_backend_url_table`, `_backend_api_key_table`, `_BACKEND_CLIENT`), plus a new file in `src/config/models/` and, if it needs a distinct HTTP client, one in `src/nlp/llm/backends/`. Then point any role at it in `.env.providers` (e.g. `LLM_ROL_GENERATE=claude,claude-haiku-4-5`). No changes to graph or node code.

## 🔄 Ingestion Pipeline

All ingestion modes share the same pipeline: **extract → chunk → embed → normalize → index → persist**.

```
Source (file / URL / domain)
         │
         ▼
  Text extraction
  (pypdf / BeautifulSoup4 / readability-lxml)
         │
         ▼
  chunk_text(text)
  ├── chunk_size:    500 chars
  └── chunk_overlap: 100 chars  (sliding window)
         │
         ▼
  FlagModel.encode(chunks)        ← BAAI/bge-small-en-v1.5
  numpy float32 cast
  faiss.normalize_L2(embeddings)  ← inner product → cosine similarity
         │
         ▼
  Append to existing index        ← always incremental, never rebuilds
  Update vectors.npy
  Update metadata.pkl
  Write index.faiss
```

### Ingestion modes

| Command                         | Source                       | Use case                  |
| ------------------------------- | ---------------------------- | ------------------------- |
| `ingest <cat> <col>`            | Local files (PDF, HTML, TXT) | Books, exported docs      |
| `ingest-url <cat> <col> <url>`  | Single URL                   | Articles, reference pages |
| `crawl <cat> <col> <start_url>` | Full domain (max 50 pages)   | Docs sites, wikis         |

All modes skip already-indexed sources via `existing_sources` deduplication — safe to re-run.

## 🎛️ Query Modes

Toggle with `/mode` in the CLI or via the `mode` field in the REST API.

|                 | HARD                                 | SOFT                                        |
| --------------- | ------------------------------------ | ------------------------------------------- |
| Top-K initial   | 15                                   | 25                                          |
| Top-K final     | 5                                    | 7                                           |
| LLM temperature | 0.2                                  | 0.2                                         |
| Prompt rules    | Strict: cite or say "not in context" | Flexible: synthesize, connect, abstract     |
| Best for        | Factual lookup, precise references   | Conceptual analysis, cross-source synthesis |

## 🌐 REST API

A FastAPI server exposes the full RAG pipeline as a REST endpoint.

```bash
python -m src.main api
# Listening on http://127.0.0.1:8000
```

### `POST /query/agent`

Runs the full LangGraph RAG pipeline (retrieve → evaluate → [reformulate →] generate → review → [correct]).

```json
{
  "question": "¿Cómo describe Freud la función de la censura en los sueños?",
  "mode": "SOFT",
  "collections": [
    "psicoanalisis/Sigmund-Freud_La-interpretacion-de-los-suenos"
  ],
  "chat_history": []
}
```

Response:

```json
{
  "answer": "...",
  "confidence": 0.8021,
  "reformulated": false,
  "review_passed": true
}
```

### `POST /query`

Direct RAG call — skips the LangGraph agent, single retrieve + generate pass.

### `GET /collections`

Lists all available collections from the vectorstore directory.

## 🛠️ Tech Stack

| Component            | Technology                                            |
| -------------------- | ----------------------------------------------------- |
| Language             | Python 3.11                                           |
| Orchestration        | LangGraph (stateful adaptive graph)                   |
| Embedding model      | `BAAI/bge-small-en-v1.5` via FlagEmbedding            |
| Vector index         | FAISS `IndexFlatIP` (exact cosine similarity)         |
| Vector normalization | L2 via `faiss.normalize_L2`                           |
| Local LLM runtime    | Any OpenAI-compatible endpoint (FastFlowLM, Ollama)   |
| Default local model  | `qwen3:8b`                                            |
| External provider    | Gemini (`gemini-2.0-flash`) via OpenAI-compatible API |
| REST API             | FastAPI + Uvicorn                                     |
| Configuration        | Pydantic Settings + `.env` files                      |
| PDF parsing          | pypdf                                                 |
| HTML extraction      | BeautifulSoup4 + readability-lxml                     |
| Numerical ops        | NumPy                                                 |
| Persistence          | `.faiss` + `.pkl` + `.npy` (no database required)     |

## 🚀 Getting Started

### Prerequisites

- Python 3.11+
- A local OpenAI-compatible LLM runtime ([FastFlowLM](https://fastflowlm.com/), [Ollama](https://ollama.com/), or similar)
- A Gemini API key for whichever roles you point at `gemini` in `.env.providers` (free tier sufficient; the example config below only uses it for answer review)

### Install

```bash
git clone https://github.com/your-username/my-assistant.git
cd my-assistant
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### Configure providers

```bash
cp .env.example .env.providers
```

Edit `.env.providers`:

```env
# Backend URLs (configured once)
LLM_FLM_URL=http://127.0.0.1:52625/v1
LLM_OLLAMA_URL=http://127.0.0.1:11434
LLM_GEMINI_URL=https://generativelanguage.googleapis.com/v1beta/openai/
GEMINI_API_KEY=your_key_here

EMBEDDER_FLM_URL=http://127.0.0.1:52625/v1
EMBEDDER_OLLAMA_URL=http://127.0.0.1:11434

# Embedder: backend,model
EMBEDDER=ollama,bge-m3

# LLM per role: backend,model (documents only ever reach roles you point at a local backend)
LLM_ROL_GENERATE=flm,qwen3.5:9b
LLM_ROL_REFORMULATE=ollama,qwen3.5:2b
LLM_ROL_REVIEW=gemini,gemini-2.5-flash-lite
LLM_ROL_SUPPLEMENT=flm,qwen3.5:9b
```

See [Multi-Provider LLM](#-multi-provider-llm) above for the full model of backends vs. roles.

### Create vectorstore directory

```bash
mkdir -p /srv/ai/vectorstores
mkdir -p /srv/ai/data
```

## 🔒 Security Notes

- **`.env.*` files are gitignored** (except `.env.example`). Never commit API keys.
- If you cloned an earlier version of this repo, **rotate your Gemini API key** — `.env.gemini` was not excluded from git in versions prior to the multi-provider refactor.
- Any role pointed at a local backend (`flm`/`ollama`) receives full document chunks in every request. Ensure your local runtime is not exposed on a public interface (`LLM_FLM_URL`/`LLM_OLLAMA_URL` should always bind to `127.0.0.1`).
- The FastAPI server also defaults to `127.0.0.1`. Do not expose it publicly without authentication and TLS.
